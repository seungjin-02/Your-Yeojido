# Cloudflare Pages + PWA 설정 안내

APK나 앱스토어 등록 없이 웹주소로 이용하고, 휴대폰 홈 화면에 설치할 수 있습니다. 소스 저장소는 GitHub Private으로 유지할 수 있습니다. **Cloudflare 계정 연결과 실제 배포는 아직 하지 않았습니다.** Supabase도 아직 연결하지 않았으므로 현재는 각 기기에 기록합니다.

## 1. 현재 여행 기록 백업

기존 GitHub Pages 사이트에서 `더보기 → 기록 내보내기`로 파일을 받습니다. 기존 주소와 새 Cloudflare 주소는 브라우저 저장 공간이 다르기 때문에 주소만 바꾸면 기존 기록이 자동으로 옮겨지지 않습니다. 기준점 이름·위치는 별도로 메모해 두세요. 기존 내보내기 파일은 여행 기록·분류·명소·색상 백업입니다.

## 2. Cloudflare에 사이트 연결

1. Cloudflare 계정 생성 후 **Workers & Pages → Create → Pages → Connect to Git**에서 GitHub를 연결합니다. 대시보드 표현은 변경될 수 있습니다.
2. GitHub 연결 권한은 `seungjin-02/Your-Yeojido` 저장소를 선택합니다. Private 저장소도 연결 가능합니다.
3. 다음 값으로 배포합니다.

| 항목 | 값 |
| --- | --- |
| Production branch | `main` |
| Framework preset | `Vite` 또는 `None` |
| Build command | `npm run build -- --base=/` |
| Build output directory | `dist` |
| Root directory | 저장소 루트 |
| Environment variable | `NODE_VERSION=24` |

4. 배포가 성공하면 `https://프로젝트이름.pages.dev` 주소를 받습니다.
5. 새 주소에서 `더보기 → 기록 가져오기`로 1단계 백업을 가져옵니다. 지도·기록·모바일 검색·오프라인 재접속을 확인합니다.
6. 이 확인이 끝난 후 GitHub `Settings → General → Danger Zone → Change repository visibility`에서 Private으로 변경합니다. 기존 GitHub Pages 주소는 요금제에 따라 중단될 수 있으므로 친구에게는 새 주소를 공유합니다. **현재 저장소 공개 여부는 변경하지 않았습니다.**

Private은 소스를 숨기는 설정입니다. 배포 사이트 자체는 링크를 아는 사람이 열 수 있습니다. 로그인 후 여행 기록은 계정별로 분리됩니다.

## 3. 휴대폰에서 앱처럼 사용

- 웹주소만 열어도 모바일 화면으로 바로 사용할 수 있습니다.
- Android Chrome: `더보기 → 앱처럼 사용하기 → 홈 화면에 설치`. 설치 버튼이 없으면 브라우저 `⋮ → 홈 화면에 추가 → 설치`를 사용합니다.
- iPhone Safari: `공유 → 홈 화면에 추가 → 추가`를 선택합니다. iOS에서는 사이트가 자동 설치 창을 띄울 수 없습니다.
- 카카오톡 등의 인앱 브라우저라면 Chrome 또는 Safari로 열어 설치합니다.
- 설치 후에는 앱 아이콘과 주소창 없는 화면을 제공합니다. 최초 온라인 접속에서 지도 파일 약 7 MiB를 저장한 뒤에는 지도·로컬 여행 기록을 오프라인으로 열 수 있습니다. 저장 공간 정리나 OS 정책으로 캐시가 제거되면 다시 온라인 접속이 필요합니다.
- 상세 주소 검색·로그인·기기 간 동기화는 인터넷이 필요합니다. 설치한 앱과 브라우저는 OS·브라우저에 따라 저장 공간이 다를 수 있습니다. 기록이 자동으로 같아진다고 가정하지 말고 4단계의 같은 계정으로 로그인하세요.
- 새 버전은 `더보기 → 앱처럼 사용하기 → 새 버전으로 업데이트`에서 적용합니다. 기록 작성 중 강제로 새로고침하지 않습니다.

## 4. 나중에 Supabase 연결

### 프로젝트와 DB

1. Supabase 프로젝트를 생성합니다. 데이터베이스 비밀번호는 본인이 보관하고 소스·채팅에 올리지 않습니다.
2. SQL Editor에서 `supabase/migrations/202611050001_travel_sync.sql`을 한 번 실행합니다.
3. 이 스크립트는 사용자별 여행 데이터, 다른 사용자의 접근을 막는 RLS, 동시 수정을 감지하는 저장 함수를 만듭니다. `service_role` 키는 앱에 필요하지 않습니다.

### 이메일 인증 코드

1. Authentication에서 Email 로그인을 활성화합니다.
2. Email Templates의 **Magic Link** 본문을 코드 방식으로 바꿉니다. 신규 가입 확인 메일에도 코드를 사용하도록 Confirm signup 템플릿을 확인합니다. 예:

```html
<h2>나의 여지도 로그인</h2>
<p>인증 코드: <strong>{{ .Token }}</strong></p>
```

3. URL Configuration의 Site URL에 실제 `https://프로젝트이름.pages.dev` 주소를 등록합니다. 이 앱은 이메일 링크 이동 대신 코드 입력을 쓰므로 앱 전용 딥링크는 필요하지 않습니다.
4. 친구들에게도 이메일을 보내려면 SMTP 발신 설정을 완료합니다. Supabase 기본 메일 서비스는 허용 수신자·발송량에 제한이 있습니다. 인증 코드 재전송 속도 제한도 프로젝트 설정에 따릅니다.

### 공개 환경변수

Supabase 프로젝트 설정에서 Project URL과 **publishable key**를 복사해 Cloudflare Pages의 Production 환경변수에 설정합니다.

```text
VITE_SUPABASE_URL=https://프로젝트ID.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=공개_publishable_key
```

구형 프로젝트의 `anon` 공개 키를 쓰면 `VITE_SUPABASE_ANON_KEY`도 지원합니다. `service_role`, `sb_secret_...`, DB 비밀번호는 절대 `VITE_` 변수에 넣지 마세요. `VITE_` 값은 브라우저에 포함됩니다.

변수 저장 후 **새 빌드로 재배포**합니다. 로컬 개발은 `.env.example`을 `.env.local`로 복사하고 같은 공개 설정을 넣으면 됩니다. 서버 설정이 없을 때는 `계정과 동기화`에 연결 준비 중 안내가 보이며 기존 로컬 기능은 계속 작동합니다.

### 첫 로그인과 기존 기록 이관

1. `더보기 → 계정과 동기화`에서 이메일을 입력하고 인증 코드를 받습니다.
2. 코드를 입력하면 계정별 공간으로 전환됩니다. 로그인 전 기록은 별도로 보관합니다.
3. 새 계정으로 기존 기록을 옮기려면 `로그인 전 기록 가져오기`를 선택합니다. 현재 계정 기록은 파일로 백업한 뒤 교체합니다. 자동 병합은 하지 않습니다.
4. 다른 휴대폰 또는 홈 화면 PWA에서도 **같은 이메일**로 로그인하면 클라우드 기록을 불러옵니다. 친구 개인 기록은 각자의 이메일로 로그인합니다.
5. 두 기기에서 동시에 수정하면 동기화를 멈추고 기록 선택을 요청합니다. 선택하지 않은 쪽을 파일로 백업하고 명시적으로 교체합니다. 이 전체 동기화 백업 파일도 `기록 가져오기`로 복원할 수 있으며 기준점도 포함합니다.
6. 로그아웃하면 이 기기의 로그인 전 기록으로 돌아옵니다. 계정별 오프라인 사본은 이 기기에 남겨 재로그인 때 이어 쓰며, 기기 저장소의 암호화 기능은 제공하지 않습니다.

방문 기록·명소·북마크·분류·색상·기준점 이름/좌표가 동기화됩니다. 언어·일시적인 검색과 화면 상태는 기기별로 유지됩니다. 자동 동기화는 앱이 열려 있을 때 변경 후, 재접속·화면 복귀 시, 약 20초 간격으로 확인합니다. 앱이 완전히 닫힌 동안 백그라운드 동기화를 보장하지 않습니다.

## 배포 전 확인

- 새 주소에서 기존 백업을 복원하고 여행 기록 수가 맞는지 확인
- 홈 화면 설치와 오프라인 재접속 확인
- Supabase 연결 후 웹 ↔ 홈 화면 앱의 같은 계정 동기화 확인
- 서로 다른 두 계정의 기록이 분리되는지 확인
- 실제 Android Chrome·iPhone Safari에서도 설치와 로그인 확인

Supabase 실제 서비스 연결 및 물리 기기 검증은 아직 수행하지 않았습니다. 코드에서는 모의 서버의 두 브라우저와 PostgreSQL 기반 테스트로 동기화·충돌·계정 격리를 검증합니다.
